Chapter Purpose

This chapter defines the target OCI VCN architecture and traffic flows for the Exadata-ready networking baseline. It is written as a network design chapter, not as an Exadata deployment chapter.
For this PoC, all network artifacts are created in the one assigned Partner/<assigned PoC compartment> compartment. A production design can place network, security, database, application, administration, and logging artifacts in separate compartments to enforce ownership and separation of duties.

Target Traffic Flows

4.1 Administrator SSH

Item Value
Source OCI Cloud Shell through an approved Bastion VM, or OCI Bastion Service
Destination Target Exadata VM node private client IPs or administrative private hosts
Protocol TCP
Port 22
Control Register the originating Cloud Shell public IP as a /32 TCP 22 ingress rule in nsg-bastion-admin; allow least-privilege SSH from nsg-bastion-admin to nsg-exadata-client
Rule Do not expose the Bastion VM or Exadata SSH to 0.0.0.0/0.

4.2 Application database traffic

Item Value
Source nsg-applications and approved hybrid app CIDRs
Destination nsg-exadata-client
Protocol TCP
Port TCP 1521 over private subnets for this guide. For production TCPS on 2484, click here.
Target SCAN listener and RAC database service, not node-specific SID
Rule Public load balancer must never forward directly to database listener ports.

4.3 Database Tools traffic

Item Value
Source nsg-dbtools-endpoint
Destination nsg-exadata-client
Protocol TCP
Port TCP 1521 over private subnets for this guide. For production TCPS on 2484, click here.
Rule Database Tools access is private only.

4.4 Backup and recovery traffic

Item Value
Source Target Exadata backup subnet
Destination Oracle Services Network through Service Gateway
Protocol TCP
Port 443
Rule Backup path must not require public IP addresses.

4.5 OCI service traffic

Item Value
Source Private subnets that require OCI APIs
Destination Oracle Services Network through Service Gateway
Protocol TCP
Port 443
Use cases Object Storage, Autonomous Recovery Service paths, YUM repositories, IAM, Vault, Monitoring, Events, Logging

4.6 Outbound public traffic

Item Value
Source Private subnets with approved outbound dependencies
Destination Public internet endpoints not supported by Service Gateway
Protocol Approved ports only
Target gw-nat
Rule NAT Gateway is outbound-only and must not be used to justify inbound public database exposure.

Exadata Deployment Inputs

The PoC implementation team should use this network baseline as follows:

Exadata deployment input Value from this workbook
VCN VCN-<compartment-name> by default, for example VCN-LAD-01
Client subnet subnet-dbclient, 10.0.1.0/24
Backup subnet subnet-dbbackup, 10.0.2.0/24
Client NSG nsg-exadata-client
Backup access control sl-backup
Hostname prefix Must be compatible with VCN and subnet DNS labels
SCAN resolution Relies on VCN DNS resolver and correct domain labels
Backup access Relies on Service Gateway and backup subnet egress TCP 443
Admin access Uses OCI Cloud Shell through an approved Bastion VM, or OCI Bastion Service

Acceptance Criteria

The architecture is approved when:

  • Database, application, public ingress, tooling, backup, and administration zones are separated.
  • The target Exadata subnets are private and have enough address capacity for scale-out.
  • Public ingress is isolated to the load balancer subnet.
  • No direct internet route exists for the target Exadata client or backup subnets.
  • Route tables and NSGs are aligned to the traffic flows in this chapter.
