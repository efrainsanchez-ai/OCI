Project Purpose

This runbook defines and implements an end-to-end Oracle Cloud Infrastructure (OCI) proof of concept in one assigned Partner child compartment. It starts with the Virtual Cloud Network (VCN) baseline in the pre-created (root)/Partner/LAD-01 compartment by default, then continues through the imported Exadata implementation, database creation, automatic backup, credential secret, and OCI Database Management workbooks. The assigned child compartment name can change for other deployments.
The runbook now covers the complete PoC implementation sequence:
  • VCN design.
  • CIDR planning.
  • Subnet layout.
  • DNS labels and resolver posture.
  • Gateways.
  • Route tables.
  • Network Security Groups (NSGs).
  • Bastion or administrator access path.
  • Private service access to Oracle Services Network.
  • Observability and security posture for the network baseline.
  • Bastion VM creation when an approved jump-host exception is used.
  • Exadata Database Service on Exascale Infrastructure cluster creation.
  • Two-node cluster upscale.
  • Container database and pluggable database creation.
  • Automatic backups through Autonomous Recovery Service.
  • Database credential secrets through OCI Vault.
  • OCI Database Management enablement and validation.
The runbook remains scoped to a PoC deployment model. It does not define production governance, enterprise landing-zone policy, or application release management.

Design Basis

The target ExaDB-XS environment depends on a private OCI networking baseline. The VCN baseline uses 10.0.0.0/16 by default. Chapter 05 lets you override the VCN CIDR when your assigned PoC environment requires a different non-overlapping range.

Network component CIDR Purpose
VCN 10.0.0.0/16 Dedicated network boundary for the Exadata-ready network
Bastion / administrator access 10.0.0.0/24 Controlled SSH administration path
Exadata client subnet 10.0.1.0/24 Target Exadata client, SCAN, VIP, and SQL*Net traffic
Exadata backup subnet 10.0.2.0/24 Backup and recovery service traffic
Database Tools private endpoint 10.0.3.0/28 Private Database Tools endpoint access
Public load balancer subnet 10.0.10.0/24 Public entry point for application tiers, not direct database access
Applications subnet 10.0.11.0/24 ORDS, APEX, middleware, application services, AI agents

The source workbook also establishes these security principles:

  • Exadata client and backup access must be private.
  • Applications should connect to the target database through SCAN and database services, not public IP addresses.
  • SQL*Net must be allowed only from approved application, database tooling, or hybrid network sources.
  • SSH must be allowed only through a controlled bastion path.
  • Backup and OCI service traffic should use a Service Gateway where possible.
  • NAT Gateway is created for controlled outbound access that cannot use Service Gateway.
  • Passwords, keys, and tokens are managed outside this workbook, normally with OCI Vault and Secret Management.

Success Criteria

The VCN baseline is complete when:

  • The VCN exists with the selected CIDR, defaulting to 10.0.0.0/16, and DNS support enabled.
  • All required subnets exist with correct CIDRs, route tables, DNS labels, and public/private posture.
  • The Exadata client and backup subnets are private and do not allow public IP assignment.
  • Service Gateway is configured for private access to Oracle Services Network.
  • NAT Gateway exists only if private workloads require outbound access to non-Oracle public endpoints.
  • Internet Gateway is attached only for the admin subnet and public load balancer subnet.
  • NSGs enforce least-privilege access between application, database, tooling, bastion, and service paths.
  • Required ICMP rules for Path MTU Discovery and VCN connectivity errors are present.
  • VCN Flow Logs are enabled for security-relevant subnets or VNICs.
  • OCIDs and DNS labels are documented for the Exadata Exascale implementation team.

Initialize the Workbook Environment

Use ~/workbook as the workbook working directory. Store all helper scripts, generated JSON artifacts, temporary OCI CLI output, and environment files under this directory. If your shell is in $HOME, this is the local ./workbook directory.

Create the workbook directory in your home folder, then create or update ~/workbook/cli.env. Start the file with only the tenancy and region placeholders; later workbook steps add compartment IDs, created OCIDs, route-table IDs, gateway IDs, subnet IDs, NSG IDs, regional service IDs, and approved CIDR variables through upsert_cli_env.

BASH 01 - Initialize workbook environment

Bash
Objective: Create the workbook directory, initialize ~/workbook/cli.env, create ~/workbook/helpers.sh, source the helpers, load current variables, and display one setup report. 
wb00_card01() {
mkdir -p ~/workbook
cat > ~/workbook/cli.env <<'EOF'
set -a
TENANCY_ID="<tenancy_ocid>"
REGION="<oci_region>"
set +a
EOF
chmod 600 ~/workbook/cli.env

cat > ~/workbook/helpers.sh <<'EOF'
WORKBOOK_DIR="${WORKBOOK_DIR:-$HOME/workbook}"
CLI_ENV="${CLI_ENV:-$WORKBOOK_DIR/cli.env}"

load_cli_env() {
  if [ ! -f "$CLI_ENV" ]; then
    printf '%s does not exist. Create ~/workbook/cli.env before continuing.\n' "$CLI_ENV" >&2
    return 1
  fi
  . "$CLI_ENV"
}

upsert_cli_env() {
  KEY="${1:-}"
  VALUE="${2:-}"
  if [ -z "$KEY" ]; then
    printf 'cli.env key is missing. Use upsert_cli_env KEY VALUE.\n' >&2
    return 1
  fi
  case "$KEY" in
    ""|*[!A-Z0-9_]*)
      printf 'Invalid cli.env key: %s\n' "$KEY" >&2
      return 1
      ;;
  esac
  if [ -z "$VALUE" ] || [ "$VALUE" = "null" ]; then
    printf '%s was not resolved. Review the command that produced this value before continuing.\n' "$KEY" >&2
    return 1
  fi
  mkdir -p "$WORKBOOK_DIR"
  touch "$CLI_ENV"
  chmod 600 "$CLI_ENV"
  if [ ! -s "$CLI_ENV" ]; then
    printf 'set -a\nset +a\n' > "$CLI_ENV"
  fi
  if ! grep -qx 'set -a' "$CLI_ENV"; then
    TMP_ENV="$(mktemp "$WORKBOOK_DIR/cli-env.XXXXXX")"
    {
      printf 'set -a\n'
      cat "$CLI_ENV"
    } > "$TMP_ENV"
    mv "$TMP_ENV" "$CLI_ENV"
  fi
  if ! grep -qx 'set +a' "$CLI_ENV"; then
    printf 'set +a\n' >> "$CLI_ENV"
  fi
  ESCAPED_VALUE="$(printf '%q' "$VALUE")"
  TMP_ENV="$(mktemp "$WORKBOOK_DIR/cli-env.XXXXXX")"
  awk -v key="$KEY" -v value="$ESCAPED_VALUE" '
    BEGIN {
      prefix = key "="
      inserted = 0
    }
    index($0, prefix) == 1 {
      next
    }
    $0 == "set +a" && inserted == 0 {
      print key "=" value
      inserted = 1
    }
    {
      print
    }
    END {
      if (inserted == 0) {
        print key "=" value
      }
    }
  ' "$CLI_ENV" > "$TMP_ENV"
  mv "$TMP_ENV" "$CLI_ENV"
  chmod 600 "$CLI_ENV"
  export "$KEY=$VALUE"
  printf '%-18s | %s\n%-18s | %s\n%-18s | %s\n\n' \
    "VARIABLE" "VALUE" \
    "------------------" "-----" \
    "$KEY" "$VALUE"
}

capture_oci_id() {
  KEY="$1"
  shift
  mkdir -p "$WORKBOOK_DIR"
  TMP_OUT="$(mktemp "$WORKBOOK_DIR/oci-cli-output.XXXXXX.txt")"
  if ! VALUE="$("$@" --query 'data.id' --raw-output)"; then
    rm -f "$TMP_OUT"
    printf 'OCI command failed while resolving %s.\n' "$KEY" >&2
    return 1
  fi
  printf '%s\n' "$VALUE" > "$TMP_OUT"
  rm -f "$TMP_OUT"
  upsert_cli_env "$KEY" "$VALUE" >/dev/null
}
EOF
chmod 700 ~/workbook/helpers.sh

cd ~/workbook
. ./helpers.sh
load_cli_env

clear
printf '%-18s | %s\n' \
  "ITEM" "VALUE" \
  "------------------" "-----" \
  "WORKBOOK_DIR" "$WORKBOOK_DIR" \
  "CLI_ENV" "$CLI_ENV" \
  "HELPERS" "$HOME/workbook/helpers.sh" \
  "HELPERS_LOADED" "yes"
printf '\n%s\n' "wb00_card01"
}

wb00_card01

Because ~/workbook/cli.env starts with set -a and ends with set +a, variables loaded through load_cli_env are exported into the current shell session.

Discover and store prerequisite variables

Workbook prerequisite variables such as TENANCY_ID, REGION, POC_PARENT_COMPARTMENT_NAME, POC_COMPARTMENT_NAME, and POC_COMPARTMENT_OCID are stored in ~/workbook/cli.env. This PoC workbook uses one pre-created compartment for every artifact: (root) / Partner/LAD-01 by default. The assigned compartment name can change by environment. The scripts ask for that compartment name, resolve it under Partner, and store POC_COMPARTMENT_OCID. The implementation runbook later aliases the workbook compartment variables to that same OCID when it creates network artifacts.

Run the following commands from an OCI Cloud Shell session. Cloud Shell provides the OCI CLI and authenticated tenancy context; the card below reads tenancy and region from the active OCI CLI profile, then stores both values in ~/workbook/cli.env.

BASH 02 - Discover and save profile values

Bash
Objective: Load workbook helpers, read tenancy and region from the active OCI CLI profile with the original ~/.oci/config method, then save both values in ~/workbook/cli.env. 
wb00_card02() {
cd ~/workbook

if [ ! -f ./helpers.sh ]; then
  printf 'Workbook helpers are not available. Create ~/workbook/helpers.sh before continuing.\n' >&2
elif ! . ./helpers.sh; then
  printf 'Workbook helpers could not be loaded. Review ~/workbook/helpers.sh before continuing.\n' >&2
elif ! load_cli_env; then
  :
else
  OCI_CONFIG_FILE="${OCI_CLI_CONFIG_FILE:-$HOME/.oci/config}"
  OCI_CONFIG_PROFILE="${OCI_CLI_PROFILE:-DEFAULT}"

  TENANCY_ID="$(
    awk -F= -v profile="$OCI_CONFIG_PROFILE" '
      $0 == "[" profile "]" { in_profile=1; next }
      /^\[/ { in_profile=0 }
      in_profile && $1 ~ /^[[:space:]]*tenancy[[:space:]]*$/ {
        gsub(/[[:space:]]/, "", $2)
        print $2
        exit
      }
    ' "$OCI_CONFIG_FILE"
  )"

  REGION="$(
    awk -F= -v profile="$OCI_CONFIG_PROFILE" '
      $0 == "[" profile "]" { in_profile=1; next }
      /^\[/ { in_profile=0 }
      in_profile && $1 ~ /^[[:space:]]*region[[:space:]]*$/ {
        gsub(/[[:space:]]/, "", $2)
        print $2
        exit
      }
    ' "$OCI_CONFIG_FILE"
  )"
fi

clear
if ! command -v upsert_cli_env >/dev/null 2>&1; then
  printf 'Workbook helpers are not loaded. Run: cd ~/workbook && . ./helpers.sh\n' >&2
else
  upsert_cli_env TENANCY_ID "$TENANCY_ID"
  upsert_cli_env REGION "$REGION"
fi

printf '\n%s\n' "wb00_card02"
}

BASH 03 - Store PoC compartment path

Bash
Objective: Ask for both the parent compartment name and the assigned PoC child compartment name, resolve both compartment OCIDs, then save all PoC compartment values in ~/workbook/cli.env. 
wb00_card03() {
if ! command -v upsert_cli_env >/dev/null 2>&1 || \
   ! command -v load_cli_env >/dev/null 2>&1; then
  printf 'Workbook helpers are not loaded. Run: cd ~/workbook && . ./helpers.sh\n' >&2
  return 1
elif ! load_cli_env; then
  return 1
elif [ -z "$TENANCY_ID" ] || [ "$TENANCY_ID" = "<tenancy_ocid>" ]; then
  printf 'TENANCY_ID is not set. Run BASH 02 to discover and save TENANCY_ID before discovering the PoC compartment.\n' >&2
  return 1
elif [ "${TENANCY_ID#ocid1.tenancy.oc1}" = "$TENANCY_ID" ]; then
  printf 'TENANCY_ID must be a tenancy OCID starting with ocid1.tenancy.oc1. Current value: %s\n' \
    "$TENANCY_ID" >&2
  return 1
else
  printf 'Enter parent compartment name [Partner]: ' >&2
  IFS= read -r POC_PARENT_COMPARTMENT_NAME
  POC_PARENT_COMPARTMENT_NAME="${POC_PARENT_COMPARTMENT_NAME:-Partner}"
  printf 'Enter assigned PoC compartment name under %s [LAD-01]: ' "$POC_PARENT_COMPARTMENT_NAME" >&2
  IFS= read -r POC_COMPARTMENT_NAME
  POC_COMPARTMENT_NAME="${POC_COMPARTMENT_NAME:-LAD-01}"

  POC_PARENT_COMPARTMENT_OCID="$(
    oci iam compartment list \
      --compartment-id "$TENANCY_ID" \
      --all \
      --query "data[?name=='$POC_PARENT_COMPARTMENT_NAME' && \"lifecycle-state\"=='ACTIVE'].id | [0]" \
      --raw-output
  )"

  if [ -z "$POC_PARENT_COMPARTMENT_OCID" ] || [ "$POC_PARENT_COMPARTMENT_OCID" = "null" ]; then
    printf 'STOP: Parent compartment "%s" was not found under the tenancy root.\n' \
      "$POC_PARENT_COMPARTMENT_NAME" >&2
  else
    POC_COMPARTMENT_OCID="$(
      oci iam compartment list \
        --compartment-id "$POC_PARENT_COMPARTMENT_OCID" \
        --all \
        --query "data[?name=='$POC_COMPARTMENT_NAME' && \"lifecycle-state\"=='ACTIVE'].id | [0]" \
        --raw-output
    )"

    if [ -z "$POC_COMPARTMENT_OCID" ] || [ "$POC_COMPARTMENT_OCID" = "null" ]; then
      printf 'STOP: PoC compartment "%s/%s" was not found.\n' \
        "$POC_PARENT_COMPARTMENT_NAME" "$POC_COMPARTMENT_NAME" >&2
    else
      upsert_cli_env POC_PARENT_COMPARTMENT_NAME "$POC_PARENT_COMPARTMENT_NAME" >/dev/null
      upsert_cli_env POC_PARENT_COMPARTMENT_OCID "$POC_PARENT_COMPARTMENT_OCID" >/dev/null
      upsert_cli_env POC_COMPARTMENT_NAME "$POC_COMPARTMENT_NAME" >/dev/null
      upsert_cli_env POC_COMPARTMENT_OCID "$POC_COMPARTMENT_OCID" >/dev/null
    fi
  fi
fi

clear
printf '%-32s | %s\n' \
  "VARIABLE" "VALUE" \
  "--------------------------------" "-----" \
  "TENANCY_ID" "$TENANCY_ID" \
  "REGION" "$REGION" \
  "POC_PARENT_COMPARTMENT_NAME" "$POC_PARENT_COMPARTMENT_NAME" \
  "POC_PARENT_COMPARTMENT_OCID" "$POC_PARENT_COMPARTMENT_OCID" \
  "POC_COMPARTMENT_NAME" "$POC_COMPARTMENT_NAME" \
  "POC_COMPARTMENT_OCID" "$POC_COMPARTMENT_OCID"
printf '\n%s\n' "wb00_card03"
}

wb00_card03

PoC compartment record: This PoC uses one pre-created compartment for every workbook artifact: network, security, database-readiness, administration, application, and logging references all point to the same Partner/LAD-01 compartment by default. The single-compartment model keeps the lab easy to reset, makes OCID tracking simpler, and avoids creating production-style IAM and tagging dependencies before the network baseline is validated.

For production environments, use separate compartments for distinct ownership and lifecycle boundaries such as networking, security, database, application, administration, and logging. Separate compartments make IAM least privilege easier to enforce, reduce accidental cross-team changes, support different budgets and quotas, improve audit scoping, and allow backup, retention, tagging, and change-control policies to vary by operational domain.

Do not record placeholder compartment OCIDs. BASH 03 discovers the real Partner/LAD-01 compartment OCID and stores only the PoC compartment variables. The implementation runbook records the other compartment aliases later.

How capture_oci_id works

capture_oci_id is a workbook helper function defined in ~/workbook/helpers.sh. It is not part of OCI CLI. Use capture_oci_id <CLI_ENV_KEY> <oci command...> for create commands that return the new resource under data.id.

When the helper runs, it:

  • Executes the OCI CLI command passed after the key with --query 'data.id' --raw-output.
  • Writes the captured OCID output to a temporary text file under ~/workbook.
  • Calls upsert_cli_env quietly, which validates that the command returned a non-empty value.
  • Appends or updates <KEY>=<OCID> in ~/workbook/cli.env.
  • Exports the updated variable into the current shell without printing the standard variable table.

Key Implementation Focus

Treat this workbook as the readiness baseline for the Exadata Exascale deployment. The important items to carry forward are validated private subnets, stable DNS labels, least-privilege NSGs, service-access routes, observability coverage, and recorded OCIDs so the implementation team can proceed with a clear network baseline.
