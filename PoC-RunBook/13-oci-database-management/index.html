Section purpose

This section enables and validates OCI Database Management Diagnostics & Management for the existing Exadata Database Service on Exascale Infrastructure container database CDB01 and its pluggable databases, including default pluggable database PDB01. The workflow uses OCI Cloud Shell, OCI CLI target version 3.73.1, the existing subnet-dbtools subnet for the Database Management private endpoint, and the SYSTEM password secret created in Chapter 12.
Oracle documentation describes Diagnostics & Management for Oracle Cloud Databases in Base Database Service, ExaDB-D, and ExaDB-XS as available through management options. For ExaDB-XS and RAC-style access, the enablement panel requires an appropriate Database Management private endpoint that can reach the Oracle Cloud Database in the VCN. This workbook therefore creates or reuses a DNS-resolution-enabled Database Management private endpoint in subnet-dbtools, not the client, backup, or admin subnet.

Required Database Management inputs

The long-form variable inventory is maintained separately from this chapter and is linked from the workbook home page. This chapter reuses REGION, DATABASE_COMPARTMENT_OCID, VCN_OCID, SUBNET_DBTOOLS_OCID, NSG_DBTOOLS_OCID, CDB_OCID, CDB_NAME, PDB_NAME, CDB_SYSTEM_SECRET_OCID, and DBMGMT_SYSTEM_SECRET_OCID from earlier chapters.

Variable Purpose
DBMGMT_PRIVATE_ENDPOINT_NAME Display name for the Database Management private endpoint. Default: dbmgmt_pe_exadata. Database Management private endpoint names must begin with a letter and contain only letters, numbers, and underscores.
DBMGMT_PRIVATE_ENDPOINT_OCID Database Management private endpoint OCID captured for CDB and PDB enablement.
DBMGMT_MANAGEMENT_TYPE Diagnostics & Management type. Workbook value: ADVANCED, which corresponds to full management.
DBMGMT_CREDENTIAL_USERNAME Database user name used for Database Management. Default: SYSTEM.
DBMGMT_CDB_SERVICE_NAME CDB service name used by the Database API enablement payload. Derived from the current CDB connection string.
DBMGMT_PROTOCOL Listener protocol used by the Database API enablement payload. Default: TCP.
DBMGMT_PORT Listener port used by the Database API enablement payload. Default: 1521.
DBMGMT_ROLE Database role used by the Database API enablement payload. Default: NORMAL.
DBMGMT_SECRET_POLICY_NAME Dedicated IAM policy name that grants Database Management managed databases read access to the password secret. Default: DBMgmt_Resource_Policy.
CDB_SYSTEM_SECRET_OCID OCI Vault secret OCID created in Chapter 12 for the SYSTEM password.
DBMGMT_SYSTEM_SECRET_OCID Database Management alias to CDB_SYSTEM_SECRET_OCID; Chapter 13 derives it when needed.
DBMGMT_PASSWORD_SECRET_OCID Database Management credential secret OCID; defaults to DBMGMT_SYSTEM_SECRET_OCID.
DBMGMT_MANAGED_DATABASE_LIST_JSON Local JSON file captured by BASH 10 with current Database Management managed database records for the compartment.

Recommended decisions

Decision Workbook value Rationale
Management feature Diagnostics & Management Official Oracle Database Management documentation identifies this as the Oracle Databases feature used to monitor and manage Oracle Cloud Databases.
Management option ADVANCED full management Oracle documents BASIC and ADVANCED; this workbook uses ADVANCED for CDB01 and for every unmanaged PDB discovered under CDB01.
PDB enablement model Enable CDB01, then enable every unmanaged PDB in CDB01 CDB-level enablement can complete without producing managed database records for existing PDBs in this environment. This workbook therefore discovers all PDBs under CDB01, compares them with managed database records, and enables only the unmanaged PDBs.
Private endpoint subnet subnet-dbtools through SUBNET_DBTOOLS_OCID Database Management needs a private endpoint in a subnet that can reach the database. The workbook keeps management tooling separate from client, backup, and admin subnet roles.
Private endpoint RAC support --is-dns-resolution-enabled true without --is-cluster OCI CLI 3.73.1 still exposes --is-cluster, but the Database Management service rejects isCluster and instructs callers to use DNS resolution for RAC and Autonomous Database private endpoints.
DNS proxy --is-dns-resolution-enabled true The private endpoint must resolve private database host names through the Database Management private endpoint.
Network controls Reuse existing database tooling NSG baseline The private endpoint is created with NSG_DBTOOLS_OCID, which already carries the database tooling egress model toward the Exadata client NSG.
Credentials SYSTEM user plus Vault secret Oracle documentation requires database user credentials and references Vault secrets for database user passwords. This workbook uses the Chapter 12 SYSTEM secret and does not place passwords in commands.
Secret access policy Dedicated resource principal policy for dbmgmtmanageddatabase Oracle requires a resource principal policy so Managed Database resources can read database user password secrets. User ownership alone is not sufficient.
Enablement API oci raw-request for CDB and oci db pluggable-database enable-pluggable-database-management for PDBs The raw Database API payload matches the known working enableDatabaseManagement request shape for CDB01; OCI CLI 3.73.1 accepts the Database service PDB command with flattened password secret, private endpoint, service name, user name, protocol, port, and role flags.
Validation Managed database records and availability metrics Oracle documentation says successful enablement lists the Oracle Cloud Database as a Managed Database. The workbook validates managed CDB/PDB records and a lightweight availability metric surface.

BASH 03 - Create or locate the Database Management private endpoint

BASH 03 - Create or locate the Database Management private endpoint

This card is intentionally reuse-first. A tenancy can have a low limit for DNS-resolution-enabled Database Management private endpoints. If an endpoint already exists, the card reuses DBMGMT_PRIVATE_ENDPOINT_OCID from cli.env, then tries the configured endpoint name, then falls back to any ACTIVE endpoint in subnet-dbtools for the target VCN before it attempts a create operation.

Bash
Objective: Create or reuse a DNS-resolution-enabled Database Management private endpoint in subnet-dbtools. 
. ~/workbook/env.sh --quiet || return 1

wb13_card03() {
DBMGMT_NSGS_JSON="$HOME/workbook/dbmgmt-private-endpoint-nsgs.json"
DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON="$HOME/workbook/dbmgmt-private-endpoint-create-response.json"
DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT="$HOME/workbook/dbmgmt-private-endpoint-create-error.txt"

case "$DBMGMT_PRIVATE_ENDPOINT_NAME" in
  [!A-Za-z]* | *[!A-Za-z0-9_]*)
    clear
    printf '\n%s\n%s\n%s\n%s\n\n' \
      "STOP: Invalid Database Management private endpoint name." \
      "Current value: $DBMGMT_PRIVATE_ENDPOINT_NAME" \
      "Required pattern: begin with a letter; use only letters, numbers, and underscores." \
      "Action: rerun BASH 02 to correct and persist DBMGMT_PRIVATE_ENDPOINT_NAME." >&2
    return 1
    ;;
esac

printf '["%s"]\n' "$NSG_DBTOOLS_OCID" > "$DBMGMT_NSGS_JSON"

if [ -n "${DBMGMT_PRIVATE_ENDPOINT_OCID:-}" ]; then
  oci database-management private-endpoint list \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --vcn-id "$VCN_OCID" \
    --all \
    --query "data.items[?id=='$DBMGMT_PRIVATE_ENDPOINT_OCID']|[0]" \
    > "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" \
    2> "$DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT"

  DBMGMT_PRIVATE_ENDPOINT_FOUND_OCID="$(
    sed -n 's/^[[:space:]]*"id"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" | sed -n '1p'
  )"

  if [ "$DBMGMT_PRIVATE_ENDPOINT_FOUND_OCID" = "$DBMGMT_PRIVATE_ENDPOINT_OCID" ]; then
    DBMGMT_PRIVATE_ENDPOINT_ACTION="REUSED_FROM_CLI_ENV"
  else
    DBMGMT_PRIVATE_ENDPOINT_OCID=""
  fi
fi

if [ -z "${DBMGMT_PRIVATE_ENDPOINT_OCID:-}" ] || [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" = "null" ]; then
  oci database-management private-endpoint list \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --name "$DBMGMT_PRIVATE_ENDPOINT_NAME" \
    --vcn-id "$VCN_OCID" \
    --all \
    --query "data.items[?\"subnet-id\"=='$SUBNET_DBTOOLS_OCID' && \"lifecycle-state\"=='ACTIVE']|[0]" \
    > "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" \
    2> "$DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT"

  DBMGMT_PRIVATE_ENDPOINT_OCID="$(
    sed -n 's/^[[:space:]]*"id"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" | sed -n '1p'
  )"

  if [ -n "$DBMGMT_PRIVATE_ENDPOINT_OCID" ] && [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" != "null" ]; then
    DBMGMT_PRIVATE_ENDPOINT_ACTION="REUSED_EXISTING_NAME"
  fi
fi

if [ -z "${DBMGMT_PRIVATE_ENDPOINT_OCID:-}" ] || [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" = "null" ]; then
  oci database-management private-endpoint list \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --vcn-id "$VCN_OCID" \
    --all \
    --query "data.items[?\"subnet-id\"=='$SUBNET_DBTOOLS_OCID' && \"lifecycle-state\"=='ACTIVE']|[0]" \
    > "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" \
    2> "$DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT"

  DBMGMT_PRIVATE_ENDPOINT_OCID="$(
    sed -n 's/^[[:space:]]*"id"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" | sed -n '1p'
  )"

  if [ -n "$DBMGMT_PRIVATE_ENDPOINT_OCID" ] && [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" != "null" ]; then
    DBMGMT_PRIVATE_ENDPOINT_ACTION="REUSED_EXISTING_SUBNET"
  fi
fi

if [ -z "$DBMGMT_PRIVATE_ENDPOINT_OCID" ] || [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" = "null" ]; then
  DBMGMT_PRIVATE_ENDPOINT_ACTION="CREATE_SUBMITTED"
  oci database-management private-endpoint create \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --name "$DBMGMT_PRIVATE_ENDPOINT_NAME" \
    --subnet-id "$SUBNET_DBTOOLS_OCID" \
    --is-dns-resolution-enabled true \
    --nsg-ids "file://$DBMGMT_NSGS_JSON" \
    > "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" \
    2> "$DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT"

  create_status=$?
  if [ "$create_status" -ne 0 ]; then
    clear
    printf '\n%s\n%s\n%s\n%s\n%s\n\n' \
      "STOP: Unable to submit the Database Management private endpoint create request." \
      "Private endpoint name: $DBMGMT_PRIVATE_ENDPOINT_NAME" \
      "OCI CLI status: $create_status" \
      "Error file: $DBMGMT_PRIVATE_ENDPOINT_ERROR_TXT" \
      "The shell prompt is still active; rerun this card after reviewing the error file." >&2
    return 1
  fi

  DBMGMT_PRIVATE_ENDPOINT_OCID="$(
    sed -n 's/^[[:space:]]*"id"[[:space:]]*:[[:space:]]*"\([^"]*\)".*/\1/p' "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON"
  )"
fi

if [ -z "$DBMGMT_PRIVATE_ENDPOINT_OCID" ] || [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" = "null" ]; then
  DBMGMT_PRIVATE_ENDPOINT_OCID="$(
    oci database-management private-endpoint list \
      --region "$REGION" \
      --compartment-id "$DATABASE_COMPARTMENT_OCID" \
      --name "$DBMGMT_PRIVATE_ENDPOINT_NAME" \
      --vcn-id "$VCN_OCID" \
      --all \
      --query 'data.items[0].id' \
      --raw-output
  )"
fi

if [ -z "$DBMGMT_PRIVATE_ENDPOINT_OCID" ] || [ "$DBMGMT_PRIVATE_ENDPOINT_OCID" = "null" ]; then
  clear
  printf '\n%s\n%s\n%s\n%s\n\n' \
    "STOP: Unable to create or locate the Database Management private endpoint." \
    "Private endpoint name: $DBMGMT_PRIVATE_ENDPOINT_NAME" \
    "Response file: $DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" \
    "If create failed with a DNS-enabled endpoint limit, verify an ACTIVE endpoint exists in subnet-dbtools and rerun this card." >&2
  return 1
fi

upsert_cli_env DBMGMT_PRIVATE_ENDPOINT_OCID "$DBMGMT_PRIVATE_ENDPOINT_OCID" >/dev/null
clear
printf '%-43s | %s\n' \
  "VARIABLE" "VALUE" \
  "-------------------------------------------" "-----" \
  "DBMGMT_PRIVATE_ENDPOINT_ACTION" "$DBMGMT_PRIVATE_ENDPOINT_ACTION" \
  "DBMGMT_PRIVATE_ENDPOINT_OCID" "$DBMGMT_PRIVATE_ENDPOINT_OCID" \
  "DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON" "$DBMGMT_PRIVATE_ENDPOINT_RESPONSE_JSON"
printf '\n%s\n' "wb13_card03"
}

BASH 05 - Create the Database Management secret access policy

BASH 05 - Create the Database Management secret access policy

OCI user ownership of the Vault secret is not enough for enablement. Database Management reads the password secret as a managed database resource principal, so the secret compartment must include a policy that allows dbmgmtmanageddatabase to read the specific password secret. Oracle documents the specific-secret form as Allow any-user to read secret-family in compartment ABC where ALL {target.secret.id = <Secret OCID>,request.principal.type = dbmgmtmanageddatabase}.

This workbook creates or updates a dedicated IAM policy object in the assigned PoC compartment through SECURITY_COMPARTMENT_OCID identified by SECURITY_COMPARTMENT_OCID, which chapter 05 aliases to the assigned PoC compartment. IAM policy create and update operations must run in the tenancy home region, so this card uses DBMGMT_IAM_HOME_REGION, defaulting to us-phoenix-1 unless IAM_HOME_REGION or HOME_REGION is already set. The policy statement grants access only to the secret in the assigned PoC compartment and only when the caller principal type is dbmgmtmanageddatabase. The statement resolves the assigned compartment name from POC_COMPARTMENT_NAME or from SECURITY_COMPARTMENT_OCID, then uses that actual compartment name in the policy statement. The grant is intentionally scoped to the Chapter 12 password secret instead of all secrets in the compartment.

Credential follow-up in OCI

After the database-side grants are complete, the OCI UI can still show a warning on the Database Management summary page: Credential required to perform Database Management tasks is not set. Use the OCI action shown on the CDB01 Database Management page to attach the working credential for interactive management tasks.

!OCI Database Management credential warning on the CDB01 summary page

Recommended OCI flow:

Step OCI action
1 In OCI, open Database Management.
2 Open the managed database record for CDB01.
3 On the CDB01 - Summary page, review the warning banner.
4 Select Set advanced diagnostics preferred credential when you want Database Management to use the credential for diagnostics and management tasks across Performance Hub, ADDM Spotlight, AWR Explorer, and related views.
5 Use SYSTEM as the database user.
6 Select the Chapter 12 SYSTEM password secret, tracked by DBMGMT_PASSWORD_SECRET_OCID or CDB_SYSTEM_SECRET_OCID in ~/workbook/cli.env.
7 Save the credential.
8 Reopen Performance Hub or refresh the Database Management page so the service retries with the preferred credential.

Use Set session credential only for a temporary browser session when you do not want to persist a preferred credential. For repeatable workbook validation and later Database Management tasks, the preferred credential is the better match because the credential remains associated with the managed database after the current browser session ends.
