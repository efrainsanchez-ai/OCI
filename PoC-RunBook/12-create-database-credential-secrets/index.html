Section purpose

This section creates the OCI Vault resources required before OCI Database Management can use database credentials. The workbook creates or reuses a Vault in the assigned PoC compartment through SECURITY_COMPARTMENT_OCID identified by SECURITY_COMPARTMENT_OCID, which chapter 05 aliases to the assigned PoC compartment, creates or reuses an AES KMS key in that Vault, and stores the CDB_ADMIN_PASSWORD value from Chapter 10 as separate Vault secrets for the SYS and SYSTEM users.
The source password is not re-entered in this chapter. It is reused from ~/workbook/cli.env, where Chapter 10 persists CDB_ADMIN_PASSWORD for the CDB01 creation workflow. The resulting secret OCIDs are stored for Chapter 13, which uses the SYSTEM secret as the Database Management credential secret.

Required security inputs

The long-form variable inventory is linked from the workbook home page. This chapter reuses REGION, CDB_NAME, and CDB_ADMIN_PASSWORD from previous chapters and expects SECURITY_COMPARTMENT_OCID to identify the compartment that owns security services.

Variable Purpose
SECURITY_COMPARTMENT_OCID Compartment OCID for OCI Vault, KMS key, and secrets.
CDB_CREDENTIAL_VAULT_NAME Vault display name. Default: vault-01.
CDB_CREDENTIAL_VAULT_OCID Vault OCID captured after create or lookup.
CDB_CREDENTIAL_VAULT_MANAGEMENT_ENDPOINT Vault management endpoint required by KMS key commands.
CDB_CREDENTIAL_KEY_NAME KMS key display name. Default: key-01.
CDB_CREDENTIAL_KEY_OCID KMS key OCID used to encrypt the secrets.
CDB_SYS_SECRET_NAME SYS password secret name. Default: cdb01-sys-password.
CDB_SYSTEM_SECRET_NAME SYSTEM password secret name. Default: cdb01-system-password.
CDB_SYS_SECRET_OCID Vault secret OCID containing the SYS password.
CDB_SYSTEM_SECRET_OCID Vault secret OCID containing the SYSTEM password.

Recommended decisions

Decision Workbook value Rationale
Compartment placement SECURITY_COMPARTMENT_OCID Keeps Vault, KMS key, and secret governance in the assigned PoC compartment through SECURITY_COMPARTMENT_OCID instead of the database or admin compartment.
Vault type DEFAULT Uses the standard OCI Vault type for workbook credential storage unless the tenancy requires a virtual private vault.
KMS key shape AES, length 32 Uses an AES symmetric key shape for Vault secret encryption.
Secret source CDB_ADMIN_PASSWORD Reuses the password already used for CDB01 creation rather than prompting for or hardcoding a second credential value.
Secret separation Separate SYS and SYSTEM secrets Keeps user-specific secret names and OCIDs distinct even when the initial password value is the same.
Database Management credential SYSTEM secret Uses the SYSTEM credential for Chapter 13 Database Management enablement and keeps SYS available only when an approved workflow explicitly requires it.
Wait behavior No long waits Vault resources can take time to become active. Cards capture immediate outputs and validation cards tell the operator to rerun after OCI reaches ACTIVE if needed.

Vault choice before creation

OCI Vault provides the container for the encryption key and the database password secrets used by later Database Management cards. This workbook creates the Vault in SECURITY_COMPARTMENT_OCID so database credentials are governed with the rest of the security resources, not inside the assigned PoC compartment.

Oracle exposes two Vault infrastructure choices through the CLI --vault-type parameter. The workbook uses DEFAULT because this lab needs one software-protected key and two database password secrets, and the official Oracle price list shows software-protected Vault keys as Free and Vault secrets as Free. A VIRTUAL_PRIVATE Vault is appropriate when the tenancy requires dedicated/private Vault infrastructure for stronger isolation or stricter compliance controls, but it introduces a private-vault hourly charge.

Vault type Infrastructure model Isolation / compliance posture Fixed recurring charge Workbook cost view
DEFAULT Standard shared Vault infrastructure Managed KMS on the shared OCI service model No private-vault base charge Estimated at $0 for one software-protected key and two Vault secrets, based on Oracle price-list rows for software-protected keys and secrets.
VIRTUAL_PRIVATE Dedicated/private Vault partition Stronger isolation for stricter security or compliance requirements Yes - private Vault hourly/monthly charge applies even with zero keys and zero usage Higher than DEFAULT for this scenario because the fixed private-Vault charge is added before key or secret usage.

For this workbook, DEFAULT is the best fit: it avoids a recurring private-vault charge while still keeping the key and secrets in the assigned PoC compartment through SECURITY_COMPARTMENT_OCID. Revisit VIRTUAL_PRIVATE only when a formal security or compliance requirement calls for dedicated Vault infrastructure.

Key defaults before creation

OCI KMS keys encrypt Vault secret content. This workbook creates one reusable key for the CDB01 credential secrets so the SYS and SYSTEM password secrets share the same assigned PoC compartment key policy and audit surface.

The defaults are intentionally narrow: a software-protected AES key named key-01, created in vault-01 with a key shape of {"algorithm":"AES","length":32}. This is enough for Vault secret encryption in the workbook and keeps the cost posture aligned with the official Oracle price list row that lists software-protected Vault keys as Free.

Default option Workbook value Purpose
Key display name key-01 Keeps the lab key name short and aligned with the workbook Vault name vault-01.
Key algorithm AES Uses a symmetric key appropriate for Vault secret encryption.
Key length 32 Creates a 256-bit AES key shape for the secret encryption key.
Protection mode Software-protected key Matches the workbook cost and simplicity goal for one key and two secrets.
Key compartment SECURITY_COMPARTMENT_OCID Keeps key ownership with security resources instead of the database workload.
Key endpoint CDB_CREDENTIAL_VAULT_MANAGEMENT_ENDPOINT Sends KMS key commands to the Vault-specific management endpoint captured in BASH 04.

Use an HSM-protected key or dedicated key management only when a formal security policy requires hardware-backed key custody or dedicated HSM partitioning. Those options add operational and pricing considerations that are not needed for this workbook scenario.

Secret defaults before creation

OCI Vault secrets store sensitive values as encrypted secret content under a Vault and key. This workbook uses oci vault secret create-base64, so the password value is base64-encoded before it is sent to OCI, and the plaintext password is never printed in the terminal output.

The defaults intentionally create two separate secret resources from the same Chapter 10 password value, CDB_ADMIN_PASSWORD. The initial CDB creation workflow uses one administrator password for both built-in accounts, but separate Vault secrets make later automation clearer and safer because each later workflow can reference the intended database user.

Default option Workbook value Purpose
SYS secret name cdb01-sys-password Keeps the SYS credential available for approved administrative workflows without using it as the default Database Management credential.
SYSTEM secret name cdb01-system-password Stores the credential Chapter 13 uses for OCI Database Management enablement.
Secret source CDB_ADMIN_PASSWORD Reuses the CDB01 password from Chapter 10 instead of prompting for or embedding a second password.
Encryption key CDB_CREDENTIAL_KEY_OCID Encrypts both secrets with the workbook KMS key in vault-01.
Secret content format Base64 content Matches the create-base64 CLI command requirement for --secret-content-content.
Secret version label <secret-name>-v1 Gives the initial secret content a predictable version name for audit and later rotation.
Terminal output Secret OCIDs only Prints only secret identifiers; no password or base64 secret content is shown.

The workbook creates the SYSTEM secret after the SYS secret because Chapter 13 depends on DBMGMT_SYSTEM_SECRET_OCID, an alias to the SYSTEM secret OCID. If secret rotation is needed later, rotate each user-specific secret independently and update only the dependent alias for the workflow that uses it.
