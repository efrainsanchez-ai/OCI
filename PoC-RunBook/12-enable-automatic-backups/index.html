Section purpose

This section enables automatic backups for the existing container database CDB01, which was created with the default pluggable database PDB01 in Chapter 10. The backup destination is Oracle Database Autonomous Recovery Service in the assigned PoC compartment through DATABASE_COMPARTMENT_OCID. The workflow uses the existing VCN baseline from the networking runbook: subnet-db-backup, the private service route through the service gateway, and the backup subnet security list rules that permit Autonomous Recovery Service backup traffic. The nsg-exadata-backup network security group is no longer required for this workbook series.
OCI CLI 3.73.1 is the target command-line version for this workbook. The commands use documented oci recovery recovery-service-subnet create, oci recovery protection-policy-collection list-protection-policies, oci db database update, oci db database get, and oci db backup create surfaces. The database update command enables automatic backups and passes the Autonomous Recovery Service destination as a backup destination payload.

Required backup inputs

Variable Purpose
REGION OCI region loaded by ~/workbook/helpers.sh plus load_cli_env and passed explicitly to OCI CLI commands.
DATABASE_COMPARTMENT_OCID Assigned PoC compartment alias that contains VMCluster-01, dbhome_01, CDB01, and Recovery Service configuration.
VCN_OCID VCN OCID from the networking implementation runbook.
SUBNET_DB_BACKUP_OCID Backup subnet OCID mapped to subnet-db-backup; this is the subnet associated with the Recovery Service subnet.
CDB_OCID Existing CDB01 database OCID captured in Chapter 10.
CDB_NAME Container database name. Default: CDB01.
PDB_NAME Initial pluggable database name. Default: PDB01.
PROTECTION_POLICY_NAME Autonomous Recovery Service protection policy display name. Default: Bronze.

Recommended choices

Choice Workbook value Rationale
Backup destination Autonomous Recovery Service Keeps backup management in OCI-managed Recovery Service instead of unmanaged RMAN or local-only backup handling.
Recovery Service network placement subnet-db-backup Reuses the VCN component created for backup traffic and keeps backup connectivity separate from client and admin subnet flows.
Protection policy Bronze Uses the requested Recovery Service protection policy from the database compartment.
Automatic backups Enabled Moves CDB01 from the Chapter 10 lab state into the protected backup state.
Real-time data protection Service default / not enabled OCI CLI 3.73.1 does not expose a working database update flag for Zero Data Loss in this workflow; the returned DBRS destination does not enable it.
First backup Immediate named full backup Starts a manual full backup after enabling automatic backups because the update response keeps run-immediate-full-backup as false.
Database termination behavior Service/API returned default The OCI CLI 3.73.1 update response returns backup-deletion-policy and backup-retention-policy-on-terminate as null; record any required termination-retention change through the supported OCI Console/API path for the environment.
Backup window Service default Omits optional backup-window overrides so OCI chooses the default start window for the region.

BASH 03 - Create or locate the Recovery Service subnet

BASH 03 - Create or locate the Recovery Service subnet

Bash
Objective: Create or reuse the Recovery Service subnet in the assigned PoC compartment through DATABASE_COMPARTMENT_OCID by using the existing VCN backup subnet. Backup subnet ingress and egress are managed by security lists. 
. ~/workbook/env.sh --quiet || return 1
wb11_card03() {

RSS_SUBNETS_JSON="$JSON_DIR/recovery-service-subnets.json"
RSS_RESPONSE_JSON="$JSON_DIR/recovery-service-subnet-create-response.json"

printf '["%s"]\n' "$SUBNET_DB_BACKUP_OCID" > "$RSS_SUBNETS_JSON"

  oci recovery recovery-service-subnet-collection list-recovery-service-subnets \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --display-name "rss-exadata-backup" \
    --vcn-id "$VCN_OCID" \
    --lifecycle-state ACTIVE \
    --all \
    --query 'data.items[0].id' \
    --raw-output
)"

if [ -z "$RECOVERY_SERVICE_SUBNET_OCID" ] || [ "$RECOVERY_SERVICE_SUBNET_OCID" = "null" ]; then
  oci recovery recovery-service-subnet create \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --display-name "rss-exadata-backup" \
    --vcn-id "$VCN_OCID" \
    --subnets "file://$RSS_SUBNETS_JSON" \
    > "$RSS_RESPONSE_JSON"
fi

RECOVERY_SERVICE_SUBNET_OCID="$(
  oci recovery recovery-service-subnet-collection list-recovery-service-subnets \
    --region "$REGION" \
    --compartment-id "$DATABASE_COMPARTMENT_OCID" \
    --display-name "rss-exadata-backup" \
    --vcn-id "$VCN_OCID" \
    --lifecycle-state ACTIVE \
    --all \
    --query 'data.items[0].id' \
    --raw-output
)"

if [ -z "$RECOVERY_SERVICE_SUBNET_OCID" ] || [ "$RECOVERY_SERVICE_SUBNET_OCID" = "null" ]; then
  printf 'Unable to create or locate Recovery Service subnet rss-exadata-backup in the assigned PoC compartment through DATABASE_COMPARTMENT_OCID.\n' >&2
  return 1

upsert_cli_env RECOVERY_SERVICE_SUBNET_OCID "$RECOVERY_SERVICE_SUBNET_OCID" >/dev/null

printf 'RECOVERY_SERVICE_SUBNET_OCID=%s\n' "$RECOVERY_SERVICE_SUBNET_OCID"
printf '\n%s\n' "wb11_card03"

BASH 06 - Enable automatic backups for CDB01

wb11_card06() {

ENABLE_BACKUPS_RESPONSE_JSON="$JSON_DIR/cdb01-enable-automatic-backups-response.json"

The response should show auto-backup-enabled as true and DBRS as the backup destination. In OCI CLI 3.73.1 validation, backup-deletion-policy, backup-retention-policy-on-terminate, and run-immediate-full-backup remained unset in the returned database resource, so BASH 08 starts the immediate backup explicitly.

BASH 09 - Validate backup inventory

BASH 09 - Validate backup inventory

Bash
Objective: Confirm that CDB01 has an active or creating backup record after automatic backup enablement. 
. ~/workbook/env.sh --quiet || return 1
wb11_card09() {

clear
BACKUP_LIST_JSON="$(
  oci db backup list \
    --region "$REGION" \
    --database-id "$CDB_OCID" \
    --all \
    --query 'data' \
    --output json
)"

printf '%-40s | %-10s | %-11s | %s\n' \
  "DISPLAY_NAME" "STATE" "TYPE" "DURATION" \
  "----------------------------------------" "----------" "-----------" "--------"

printf '%s' "$BACKUP_LIST_JSON" \
| jq -r --arg now "$(date -u +%s)" '
    def epoch($stamp):
      $stamp
      | sub("\\.[0-9]+"; "")
      | sub("\\+00:00$"; "Z")
      | fromdateiso8601;
    def duration($start; $finish):
      if ($start // "") == "" then "unknown"
      else
        ((if ($finish // "") == "" then ($now | tonumber) else epoch($finish) end) - epoch($start)) as $seconds
        | if $seconds < 60 then "\($seconds)s"
          elif $seconds < 3600 then "\(($seconds / 60) | floor)m \($seconds % 60)s"
          else "\(($seconds / 3600) | floor)h \((($seconds % 3600) / 60) | floor)m"
          end
      end;
    .[]
    | [
        ."display-name",
        ."lifecycle-state",
        .type,
        duration(."time-started"; ."time-ended")
      ]
    | @tsv' \
| while IFS="$(printf '\t')" read -r display_name state backup_type duration_value; do
    printf '%-40s | %-10s | %-11s | %s\n' \
      "$display_name" "$state" "$backup_type" "$duration_value"
  done
printf '\n%s\n' "wb11_card09"
}

wb11_card10() {

  printf 'REQUESTED_REAL_TIME_DATA_PROTECTION_ENABLED=%s\n' "$REAL_TIME_DATA_PROTECTION_ENABLED"
  printf 'REQUESTED_BACKUP_RETENTION_POLICY_ON_TERMINATE=%s\n' "$BACKUP_RETENTION_POLICY_ON_TERMINATE"
  printf 'APPLIED_BACKUP_DELETION_POLICY=null\n'
  printf 'APPLIED_RUN_IMMEDIATE_FULL_BACKUP=false\n'
  printf 'INITIAL_BACKUP_OCID=%s\n' "${INITIAL_BACKUP_OCID:-}"
} > "$BACKUP_REPORT"

clear
"$BACKUP_REPORT_SCRIPT" "$BACKUP_REPORT"
printf '\n%s\n' "wb11_card10"
}
