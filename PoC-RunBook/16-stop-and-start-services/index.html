Section purpose

This section stops and starts the compute-heavy parts of a non-production PoC environment when the environment does not need 24/7 operation. The stop path downscales VMCluster-01 enabled ECPUs to 0, stops the bastion VM with a graceful SOFTSTOP, and validates both resources after the change. The start path restores Exadata Exascale enabled ECPUs and starts the bastion VM when the service window reopens.
This action reduces runtime consumption, but it does not make the environment free. Storage, backup retention, stopped-instance storage, public IPs, logging, observability, private endpoints, and any other provisioned paid services can continue to accrue charges. Review OCI Cost Analysis, budgets, and the current Oracle Cloud price list before using this as a recurring shutdown procedure.

Operating assumptions

Area Assumption
Environment Non-production PoC, development, or lab only. Do not use this procedure for production without a full application stop and recovery plan.
Exadata VM cluster VM_CLUSTER_OCID points to the Exadata Database Service on Exascale Infrastructure VM cluster created earlier in the workbook.
Target downscale Enabled ECPUs are set to 0. Total ECPUs are not changed by this runbook.
Bastion VM BASTION_VM_OCID points to the approved bastion VM created earlier in the workbook.
Restart plan Save the restore values from BASH 03 before downscaling so the previous enabled ECPU count can be restored when the service window reopens.

Costs that can still be charged

Downscaling enabled ECPUs to 0 and stopping the bastion VM can reduce active compute charges, but the following resources can still appear in OCI usage and cost reports:

Resource or service Why charges can continue
Exadata Exascale storage Allocated database storage, VM file system storage, sparse or smart database storage, and any additional Exascale storage capacity remain provisioned.
Database backups Existing backups, automatic backup retention, Recovery Service protection, Object Storage backup copies, and retained backup metadata can continue to consume billable storage.
Bastion VM boot and block volumes Stopping the compute instance does not delete its boot volume or any attached block volumes. Storage remains allocated until deleted.
Reserved or public IPv4 addresses A reserved public IP or other billable public IPv4 resource can continue to charge even when the VM is stopped.
Object Storage Buckets and objects created by the workbook, including uploaded SSH key files or reports, remain stored until deleted.
Vault resources This workbook uses a DEFAULT Vault. Oracle lists software-protected Vault keys and Vault secrets as free; virtual private Vaults and some HSM-protected key versions can charge if selected in another environment.
Database Management and observability Database Management, Operations Insights, Logging, VCN Flow Logs, Log Analytics, custom metrics, alarms, or other enabled management services can continue to charge according to service configuration and retained data.
Networking resources NAT Gateways, Load Balancers, Network Load Balancers, private endpoints, public IPs, and data transfer can continue to charge when provisioned or used.
Licenses and commitments Universal Credits, BYOL obligations, committed spend, support, marketplace subscriptions, and organization-specific contracts are outside this runbook and can still apply.

Use this runbook as a credit-saving control, not as a deletion procedure. To stop all charges, resources normally must be deleted and retained data must be removed according to your retention and compliance rules.

upsert_cli_env() {
  KEY="${1:-}"
  VALUE="${2:-}"
  if [ -z "$KEY" ]; then
    printf 'cli.env key is missing. Use upsert_cli_env KEY VALUE.\n' >&2
    return 1
  fi
  case "$KEY" in
    ""|*[!A-Z0-9_]*)
      printf 'Invalid cli.env key: %s\n' "$KEY" >&2
      return 1
      ;;
  esac
  if [ -z "$VALUE" ] || [ "$VALUE" = "null" ]; then
    printf '%s was not resolved. Review the command that produced this value before continuing.\n' "$KEY" >&2
    return 1
  fi
  mkdir -p "$WORKBOOK_DIR"
  touch "$CLI_ENV"
  chmod 600 "$CLI_ENV"
  if [ ! -s "$CLI_ENV" ]; then
    printf 'set -a\nset +a\n' > "$CLI_ENV"
  fi
  if ! grep -qx 'set -a' "$CLI_ENV"; then
    TMP_ENV="$(mktemp "$WORKBOOK_DIR/cli-env.XXXXXX")"
    {
      printf 'set -a\n'
      cat "$CLI_ENV"
    } > "$TMP_ENV"
    mv "$TMP_ENV" "$CLI_ENV"
  fi
  if ! grep -qx 'set +a' "$CLI_ENV"; then
    printf 'set +a\n' >> "$CLI_ENV"
  fi
  ESCAPED_VALUE="$(printf '%q' "$VALUE")"
  TMP_ENV="$(mktemp "$WORKBOOK_DIR/cli-env.XXXXXX")"
  awk -v key="$KEY" -v value="$ESCAPED_VALUE" '
    BEGIN {
      prefix = key "="
      inserted = 0
    }
    index($0, prefix) == 1 {
      next
    }
    $0 == "set +a" && inserted == 0 {
      print key "=" value
      inserted = 1
    }
    {
      print
    }
    END {
      if (inserted == 0) {
        print key "=" value
      }
    }
  ' "$CLI_ENV" > "$TMP_ENV"
  mv "$TMP_ENV" "$CLI_ENV"
  chmod 600 "$CLI_ENV"
  export "$KEY=$VALUE"
  printf '%-18s | %s\n%-18s | %s\n%-18s | %s\n\n' \
    "VARIABLE" "VALUE" \
    "------------------" "-----" \
    "$KEY" "$VALUE"
}

capture_oci_id() {
  KEY="$1"

    return 1
  fi
  printf '%s\n' "$VALUE" > "$TMP_OUT"
  rm -f "$TMP_OUT"
  upsert_cli_env "$KEY" "$VALUE"
}

  oci compute instance get \
    --region "$REGION" \
    --instance-id "$BASTION_VM_OCID" \
    --query 'data."lifecycle-state"' \
    --raw-output
)"

  RUNNING)
    BASTION_START_ACTION="SKIPPED_ALREADY_RUNNING"
    BASTION_START_STATUS="0"
    ;;
  STOPPED)
    printf 'Submitting bastion VM START request ...\n'
    oci compute instance action \
      --region "$REGION" \
      --instance-id "$BASTION_VM_OCID" \
      --action START \
      > "$BASTION_START_RESPONSE_JSON" \
      2> "$BASTION_START_ERROR_TXT"
    BASTION_START_STATUS=$?
    BASTION_START_ACTION="START_SUBMITTED"
    ;;
  *)
    clear
    printf '\n%s\n%s\n%s\n\n' \
      "STOP: Bastion VM is not in a state this card changes automatically." \
      "Current state: $BASTION_STATE" \
      "Action: wait for STOPPED or RUNNING, then rerun this card." >&2
    return 1
    ;;
esac

if [ "$BASTION_START_STATUS" -ne 0 ]; then
  clear
  printf '\n%s\n%s\n%s\n%s\n\n' \
    "STOP: Unable to start the bastion VM." \
    "OCI CLI status: $BASTION_START_STATUS" \
    "Error file: $BASTION_START_ERROR_TXT" \
    "The shell prompt is still active; the VM start was not confirmed." >&2
  return 1
fi

clear
printf '%-29s | %s\n' \
  "FIELD" "VALUE" \
  "-----------------------------" "-----" \
  "BASTION_PREVIOUS_STATE" "$BASTION_STATE" \
  "BASTION_START_ACTION" "$BASTION_START_ACTION" \
  "BASTION_START_RESPONSE_JSON" "$BASTION_START_RESPONSE_JSON" \
  "BASTION_START_ERROR_TXT" "$BASTION_START_ERROR_TXT"
printf '\n%s\n' "wb16_card08"

  oci db exadb-vm-cluster get \
    --region "$REGION" \
    --exadb-vm-cluster-id "$VM_CLUSTER_OCID" \
    --query 'data."lifecycle-state"' \
    --raw-output
)"
CURRENT_ENABLED_ECPUS="$(
  oci db exadb-vm-cluster get \
    --region "$REGION" \
    --exadb-vm-cluster-id "$VM_CLUSTER_OCID" \
    --query 'data."enabled-e-cpu-count"' \
    --raw-output
)"

if [ "$CLUSTER_STATE" != "AVAILABLE" ]; then
  clear
  printf '\n%s\n%s\n%s\n\n' \
    "STOP: VM cluster is not AVAILABLE." \
    "Current state: $CLUSTER_STATE" \
    "Action: wait for the cluster operation to finish, then rerun this card." >&2
  return 1
fi

if [ "$CURRENT_ENABLED_ECPUS" = "$SERVICE_RESTORE_ENABLED_ECPU_COUNT" ]; then
  RESTORE_ACTION="SKIPPED_ALREADY_AT_TARGET"
  RESTORE_STATUS="0"
else
  printf 'Submitting Exadata enabled ECPU restore request ...\n'
  oci db exadb-vm-cluster update \
    --region "$REGION" \
    --exadb-vm-cluster-id "$VM_CLUSTER_OCID" \
    --enabled-e-cpu-count "$SERVICE_RESTORE_ENABLED_ECPU_COUNT" \
    --force \
    > "$RESTORE_RESPONSE_JSON" \
    2> "$RESTORE_ERROR_TXT"
  RESTORE_STATUS=$?
  RESTORE_ACTION="SUBMITTED"
fi

if [ "$RESTORE_STATUS" -ne 0 ]; then
  clear
  printf '\n%s\n%s\n%s\n%s\n\n' \
    "STOP: Unable to restore enabled ECPUs." \
    "OCI CLI status: $RESTORE_STATUS" \
    "Error file: $RESTORE_ERROR_TXT" \
    "The shell prompt is still active; no successful restore was confirmed." >&2
  return 1
fi

clear
printf '%-32s | %s\n' \
  "FIELD" "VALUE" \
  "--------------------------------" "-----" \
  "RESTORE_ACTION" "$RESTORE_ACTION" \

  "RESTORE_RESPONSE_JSON" "$RESTORE_RESPONSE_JSON" \
