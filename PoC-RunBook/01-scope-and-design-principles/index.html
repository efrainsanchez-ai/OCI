Chapter Purpose

This chapter defines what the OCI PoC RunBook covers, what it intentionally excludes, and the design principles used across the full workbook sequence. The runbook uses one assigned child compartment under (root)/Partner/<assigned PoC compartment>, with (root)/Partner/LAD-01 as the default example. The assigned child compartment name can change for other deployments.
This is not a networking-only runbook. Chapters 00 through 05 create the VCN, subnet, route, security, and service-access baseline. Chapters 06 through 13 reuse that baseline to prepare the shell environment, create an approved bastion VM, deploy Exadata Database Service on Exascale Infrastructure, create the first container database, enable backups, create database credential secrets, and enable OCI Database Management.

Out of Scope

The following tasks remain intentionally excluded:

  • Enterprise landing-zone design outside the assigned PoC compartment.
  • Long-term production compartment separation, quota planning, budget controls, and chargeback.
  • Customer application deployment, ORDS/APEX deployment, AI agent deployment, and middleware installation.
  • Application release management, load testing, performance tuning, and service-level objective design.
  • Customer-specific IAM group design beyond the variables and policy objects required by these workbook cards.
  • Full disaster-recovery architecture, cross-region replication, and backup retention policy design beyond the workbook's Bronze policy PoC flow.
  • SQL*Net client wallet generation, TCPS listener hardening, and production certificate lifecycle.
  • TDE key rotation strategy beyond the credential secret artifacts required by this runbook.
  • Production monitoring integration with a customer SIEM, ITSM, or enterprise observability platform.

Architecture Principles

4.1 Private database posture

The target Exadata client and backup subnets must be private. Exadata nodes must not receive public IP addresses. Applications and administrators must reach the target database through approved private network paths.

4.2 Least privilege by network component

Security rules must be attached to the workload component, not only to the subnet. Use NSGs as the primary control so that the security policy can follow the resource VNIC rather than being coupled to all resources in a subnet.

4.3 Explicit routing

Every subnet uses a custom route table. Do not rely on default route tables for production database networks.

4.4 Separate data paths

The target Exadata client path and backup path must be separated:

Path Subnet Primary use
Client 10.0.1.0/24 SCAN, VIP, SQL*Net, application database traffic, tooling traffic
Backup 10.0.2.0/24 Backup and recovery traffic to Object Storage or Autonomous Recovery Service paths

4.5 No direct database exposure

The public load balancer subnet can expose application entry points only. It must not expose database listeners, SCAN listeners, node listeners, or SSH access to Exadata nodes.

4.6 Prefer OCI Cloud Shell administrative access

Use OCI Cloud Shell as the preferred administrator workstation because it provides an OCI-authenticated CLI environment without local OCI CLI installation or API-key configuration. Access to private resources must continue through an approved Bastion VM or OCI Bastion Service, with the originating Cloud Shell public IP registered as a source-specific /32 TCP 22 rule in the bastion NSG. Do not allow SSH from 0.0.0.0/0.

4.7 Service Gateway first

Use Service Gateway for supported Oracle services. NAT Gateway is reserved for outbound access to public endpoints that are not available through Oracle Services Network.

4.8 Build the runbook as one dependency chain

Each chapter must leave the next chapter with stable prerequisites. The network chapters write VCN, subnet, route, gateway, security-list, and NSG OCIDs. The Exadata chapters reuse those values to create infrastructure, then write database, backup, secret, and Database Management OCIDs for later validation.

4.9 Keep the PoC compartment model explicit

This PoC deliberately keeps all artifacts in one assigned compartment under (root)/Partner/<assigned PoC compartment>. Network, security, Exadata, database, backup, Vault, Database Management, administration, application, and logging artifacts use that same compartment. Role-specific variables remain in the runbook because the imported Exadata cards expect them, but Chapter 05 aliases those variables to the one assigned compartment OCID. Do not reintroduce legacy multi-compartment assumptions into executable PoC cards.

For production, place artifacts in different compartments where that enforces separation of duties and ownership boundaries. For example, networking, security, database, application, administration, and logging teams can each use separate compartments with scoped IAM policies, budgets, tagging, audit boundaries, and lifecycle controls.

Private by default Subnets hosting database, tooling, applications, and backup interfaces are private.
Public subnet scope Only the admin and public load balancer subnets should route through the Internet Gateway.
No broad SSH SSH to private hosts is allowed only from OCI Bastion, a hardened jump host, or approved administrative CIDRs.
NSG-to-NSG rules Use NSG references for intra-VCN traffic where supported.
SQL*Net private path This guide uses TCP 1521 over private subnets for validation and implementation. For production Exadata Exascale deployments that require encrypted Oracle Net with TCPS on 2484, click here.
Required ICMP preserved Keep required ICMP inside the approved private scope; do not add broad internet ingress on private NSGs.
Shared service egress Route tables provide Internet Gateway, NAT Gateway, and Service Gateway paths; the default security list keeps the baseline Oracle Services egress, and sl-backup adds backup-subnet-specific controls.
DNS controlled DNS labels are set deliberately before Exadata deployment because FQDNs and SCAN behavior depend on them.
Auditability Enable Audit service, VCN Flow Logs, Cloud Guard posture checks, and change records.
No secrets in shell output Passwords, tokens, and keys belong in OCI Vault / Secret Management or protected ~/workbook/cli.env values, not terminal summaries or generated reports.

Acceptance Criteria

This chapter is complete when the implementation team has approved:

  • The single assigned compartment model and the role-specific compartment aliases.
  • The default 10.0.0.0/16 CIDR, any approved VCN_CIDR override, and the subnet breakdown.
  • The reminder that subnet CIDRs must remain inside the selected VCN_CIDR when that value changes.
  • The use of separate Exadata client and backup subnets.
  • The NSG-first security model and the security-list model where the default security list applies broadly and sl-backup applies only to the backup subnet.
  • The Service Gateway-first service access model.
  • The administrator access model, including whether the bastion VM exception is approved.
  • The Exadata deployment, CDB creation, backup, credential secret, and Database Management chapters included in this PoC runbook.
  • The list of tasks intentionally left outside this PoC.
