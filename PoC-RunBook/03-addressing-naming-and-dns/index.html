Chapter Purpose

This chapter defines the IP addressing, subnet names, DNS labels, and resolver posture required for an Exadata-ready OCI VCN baseline.
For this PoC, these network artifacts use the one assigned Partner/<assigned PoC compartment> compartment. Production can distribute artifacts across compartments to enforce ownership and separation of duties.

DNS Label Plan

DNS labels must be selected before target Exadata provisioning because Exadata node FQDNs and SCAN resolution depend on the VCN and subnet domain labels. OCI appends oraclevcn.com automatically, so the VCN DNS label poc creates the VCN DNS domain poc.oraclevcn.com.

Resource DNS label Resulting DNS domain Notes
VCN poc poc.oraclevcn.com Stable VCN DNS label used consistently across PoC environments.
Bastion/admin subnet admin admin.poc.oraclevcn.com Short and aligned to the subnet name.
Exadata client subnet client client.poc.oraclevcn.com Used in Exadata node FQDNs.
Exadata backup subnet backup backup.poc.oraclevcn.com Used for backup interface naming context.
Database Tools subnet dbtools dbtools.poc.oraclevcn.com Private endpoint zone.
Public load balancer subnet publb publb.poc.oraclevcn.com Public entry point only.
Applications subnet apps apps.poc.oraclevcn.com Private application tier.

DNS Resolver Posture

Decision Standard
VCN DNS resolution Enabled
Resolver Internet and VCN Resolver unless enterprise DNS architecture requires custom forwarding
Exadata client DNS Must support node names and target SCAN resolution
Hybrid DNS Forwarding or conditional resolution must be designed before on-premises applications connect to the database
Public DNS Not used for database listener exposure

5.1 Hybrid DNS Considerations

If applications or administrators connect from on-premises through FastConnect or Site-to-Site VPN:

  • Confirm whether on-premises DNS can resolve *.oraclevcn.com names.
  • Configure conditional forwarding if enterprise DNS is authoritative for internal zones.
  • Confirm that target SCAN names resolve from the application network.
  • Avoid split-brain DNS where the same database service name resolves differently from different networks.
