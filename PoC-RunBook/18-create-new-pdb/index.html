Section purpose

This section creates a new pluggable database (PDB) in the existing CDB01 container database. Oracle Multitenant architecture lets one CDB host multiple isolated PDBs while sharing the CDB infrastructure and Oracle home. This reduces administrative and infrastructure overhead, supports tenant-level lifecycle operations, and makes it easier to consolidate databases while retaining logical separation for applications and schemas.
The workflow first validates the Cloud Shell environment and the target CDB, then asks for the new PDB name. It reuses the configured default CDB administrator password for the PDB administrator, CDB administrator, and existing TDE wallet password fields. The create request deliberately does not use --wait-for-state, so Cloud Shell returns as soon as OCI accepts the asynchronous request. The last card checks status until the PDB is ready.
The request disables the immediate PDB backup (createPdbBackup: false). When automatic backups are enabled on the CDB, Oracle states that the PDB cannot be recovered until the next daily backup completes successfully; it does not describe that next backup as an incremental backup. If CDB automatic backups are disabled, no daily automatic backup is scheduled, so create and validate an appropriate backup before relying on PDB recovery.
OCI CLI 3.73.1 is the target command-line version for this workbook. The commands use the documented oci db pluggable-database create, oci db pluggable-database get, and oci db pluggable-database list surfaces.

Required database inputs

Variable Purpose
REGION OCI region loaded by ~/workbook/bin/env.sh and passed explicitly to OCI CLI commands.
CDB_OCID Existing CDB01 OCID captured in Chapter 10.
CDB_NAME Existing container database name. Default: CDB01.
CDB_ADMIN_PASSWORD Existing configured default password reused for the PDB administrator, CDB administrator, and TDE wallet update fields.
NEW_PDB_NAME New PDB name requested in BASH 02. Default: PDB02.
NEW_PDB_OCID New PDB OCID captured from the asynchronous create response.

Recommended choices

Choice Workbook value Rationale
Target CDB CDB01 Reuses the established container database and its shared Oracle home.
New PDB name PDB02 Provides a distinct, short default name; replace it with an environment-approved name when needed.
PDB backup after creation Disabled No immediate PDB backup is requested. With CDB automatic backups enabled, recovery remains unavailable until Oracle's next daily backup completes successfully; otherwise arrange a backup separately.
Wallet password CDB_ADMIN_PASSWORD Reuses the configured default password for the existing TDE wallet update fields without displaying it in terminal output.
Request behavior Asynchronous Omits --wait-for-state so the browser session is not held open while OCI provisions the PDB.

BASH 01 - Preflight the CDB environment

Before submitting a create request, verify that the runbook environment has the CDB identity, region, and configured password required by the OCI API. This prevents an accidental create against an unknown CDB and confirms that the container database is available to host another isolated PDB.

BASH 01 - Preflight the CDB environment

Bash
Objective: Validate the required environment variables and the lifecycle state of CDB01 before creating a new PDB. 
wb18_card01() {
  clear
  . ~/workbook/bin/env.sh --quiet || return 1
EXPECTED_OCI_CLI_VERSION="3.73.1"
ACTUAL_OCI_CLI_VERSION="$(oci --version 2>/dev/null || true)"

missing=0
for name in REGION CDB_OCID CDB_NAME CDB_ADMIN_PASSWORD; do
  eval "value=\${$name:-}"
  if [ -z "$value" ]; then
    clear
    printf 'STOP: Missing required variable: %s\n' "$name" >&2
    missing=1
  fi
done

if [ "$missing" -ne 0 ]; then
  clear
  printf 'STOP: Run Chapter 10 and load ~/workbook/cli.env before continuing.\n' >&2
  return 1
fi

CDB_STATE="$(
  oci db database get \
    --region "$REGION" \
    --database-id "$CDB_OCID" \
    --query 'data."lifecycle-state"' \
    --raw-output
)"

if [ "$CDB_STATE" != "AVAILABLE" ]; then
  clear
  printf 'STOP: %s is %s. Wait for AVAILABLE before creating a PDB.\n' "$CDB_NAME" "$CDB_STATE" >&2
  return 1
fi

printf '%-28s | %s\n' \
  "VARIABLE" "VALUE" \
  "----------------------------" "-----" \
  "EXPECTED_OCI_CLI_VERSION" "$EXPECTED_OCI_CLI_VERSION" \
  "ACTUAL_OCI_CLI_VERSION" "$ACTUAL_OCI_CLI_VERSION" \
  "REGION" "$REGION" \
  "CDB_NAME" "$CDB_NAME" \
  "CDB_OCID" "$CDB_OCID" \
  "CDB_STATE" "$CDB_STATE" \
  "CDB_ADMIN_PASSWORD" "<loaded_from_cli_env>"
  printf '\n%s\n' "wb18_card01"
}

BASH 02 - Request the new PDB

Choose the new PDB name, then submit the OCI request. The card builds a local JSON payload so secrets are not printed in terminal output. It reuses the configured default password for the CDB administrator, PDB administrator, and existing TDE wallet password fields. The command intentionally has no waiter, so record the returned PDB OCID and use the next card to monitor provisioning.

This request sets createPdbBackup to false, so it does not take an immediate PDB backup. If CDB automatic backups are enabled, Oracle documents recovery as unavailable until the next successful daily backup; Oracle does not label that next backup as incremental. If automatic backups are disabled, schedule and validate a backup separately.

BASH 02 - Request the new PDB

Bash
Objective: Ask for the PDB name, submit an asynchronous PDB creation request, and capture the returned PDB OCID. 
wb18_card02() {
  clear
  . ~/workbook/bin/env.sh --quiet || return 1
NEW_PDB_NAME_DEFAULT="PDB02"
CREATE_PDB_JSON="$JSON_DIR/create-new-pdb.json"
CREATE_PDB_OCID_FILE="$REPORT_DIR/create-new-pdb-ocid.txt"

for name in REGION CDB_OCID CDB_NAME CDB_ADMIN_PASSWORD; do
  eval "value=\${$name:-}"
  if [ -z "$value" ]; then
    clear
    printf 'STOP: Missing required variable: %s. Run BASH 01 first.\n' "$name" >&2
    return 1
  fi
done

printf 'Enter new PDB name [%s]: ' "$NEW_PDB_NAME_DEFAULT"
IFS= read -r NEW_PDB_NAME_INPUT
NEW_PDB_NAME="${NEW_PDB_NAME_INPUT:-$NEW_PDB_NAME_DEFAULT}"
NEW_PDB_NAME="$(printf '%s' "$NEW_PDB_NAME" | tr '[:lower:]' '[:upper:]')"

case "$NEW_PDB_NAME" in
  *[!A-Z0-9]*|'')
    clear
    printf 'STOP: PDB name must start with a letter and contain only alphanumeric characters.\n' >&2
    return 1
    ;;
esac

if [ "${#NEW_PDB_NAME}" -gt 30 ] || ! printf '%s' "$NEW_PDB_NAME" | grep -q '^[A-Z]'; then
  clear
  printf 'STOP: PDB name must begin with a letter and contain at most 30 characters.\n' >&2
  return 1
fi

EXISTING_PDB_OCID="$(
  oci db pluggable-database list \
    --region "$REGION" \
    --database-id "$CDB_OCID" \
    --pdb-name "$NEW_PDB_NAME" \
    --all \
    --query 'data[0].id' \
    --raw-output
)"

if [ -n "$EXISTING_PDB_OCID" ] && [ "$EXISTING_PDB_OCID" != "null" ]; then
  clear
  printf 'STOP: PDB %s already exists in %s (%s). Choose another name.\n' "$NEW_PDB_NAME" "$CDB_NAME" "$EXISTING_PDB_OCID" >&2
  return 1
fi

jq -n \
  --arg container_database_id "$CDB_OCID" \
  --arg pdb_name "$NEW_PDB_NAME" \
  --arg default_password "$CDB_ADMIN_PASSWORD" \
  '{
    containerDatabaseId: $container_database_id,
    pdbName: $pdb_name,
    cdbAdminPassword: $default_password,
    pdbAdminPassword: $default_password,
    tdeWalletPassword: $default_password,
    createPdbBackup: false
  }' > "$CREATE_PDB_JSON"

NEW_PDB_OCID="$(
  oci db pluggable-database create \
    --region "$REGION" \
    --from-json "file://$CREATE_PDB_JSON" \
    --query 'data.id' \
    --raw-output
)"

if [ -z "$NEW_PDB_OCID" ] || [ "$NEW_PDB_OCID" = "null" ]; then
  clear
  printf 'STOP: Unable to capture NEW_PDB_OCID from the create response.\n' >&2
  return 1
fi

printf '%s\n' "$NEW_PDB_OCID" > "$CREATE_PDB_OCID_FILE"
upsert_cli_env NEW_PDB_NAME "$NEW_PDB_NAME" >/dev/null
upsert_cli_env NEW_PDB_OCID "$NEW_PDB_OCID" >/dev/null
upsert_cli_env NEW_PDB_CREATE_BACKUP "false" >/dev/null

printf '%-28s | %s\n' \
  "VARIABLE" "VALUE" \
  "----------------------------" "-----" \
  "NEW_PDB_NAME" "$NEW_PDB_NAME" \
  "NEW_PDB_OCID" "$NEW_PDB_OCID" \
  "CREATE_PDB_BACKUP" "false" \
  "REQUEST_MODE" "asynchronous; no waiter"
printf 'PDB creation request accepted. Run BASH 03 to monitor status.\n'
  printf '\n%s\n' "wb18_card02"
}

BASH 03 - Monitor PDB creation status

Use the PDB OCID returned by the create request to inspect OCI lifecycle state without holding the initial provisioning card open. While the PDB is provisioning, the card calculates elapsed time from OCI's creation timestamp to the current check. On the first AVAILABLE result, it records the observation time and calculates the completed-after duration from the same creation timestamp. OCI returns a creation timestamp but not a distinct completion timestamp, so the recorded completion duration is the first observed upper bound.

BASH 03 - Monitor PDB creation status

Bash
Objective: Display the new PDB lifecycle state plus elapsed provisioning time or the calculated first-observed completion time. 
wb18_card03() {
  clear
  . ~/workbook/bin/env.sh --quiet || return 1

for name in REGION NEW_PDB_NAME NEW_PDB_OCID; do
  value="${!name:-}"
  if [ -z "$value" ]; then
    clear
    printf 'STOP: Missing required variable: %s. Run BASH 02 first.\n' "$name" >&2
    return 1
  fi
done

PDB_JSON="$(
  oci db pluggable-database get \
    --region "$REGION" \
    --pluggable-database-id "$NEW_PDB_OCID" \
    --query 'data' \
    --output json
)"

PDB_STATE="$(printf '%s' "$PDB_JSON" | jq -r '."lifecycle-state"')"
PDB_TIME_CREATED="$(printf '%s' "$PDB_JSON" | jq -r '."time-created"')"
PDB_CREATED_EPOCH="$(
  printf '%s' "$PDB_TIME_CREATED" \
    | jq -Rr 'sub("\\.[0-9]+"; "") | sub("\\+00:00$"; "Z") | fromdateiso8601'
)"
PDB_CHECK_EPOCH="$(date -u +%s)"

if [ -z "$PDB_CREATED_EPOCH" ] || [ "$PDB_CREATED_EPOCH" = "null" ]; then
  clear
  printf 'STOP: OCI did not return a usable time-created value for %s.\n' "$NEW_PDB_NAME" >&2
  return 1
fi

PDB_AVAILABLE_EPOCH_KEY="PDB_${NEW_PDB_NAME}_AVAILABLE_OBSERVED_EPOCH"
PDB_AVAILABLE_AT_KEY="PDB_${NEW_PDB_NAME}_AVAILABLE_OBSERVED_AT"
PDB_AVAILABLE_OBSERVED_EPOCH="${!PDB_AVAILABLE_EPOCH_KEY:-}"

if [ "$PDB_STATE" = "AVAILABLE" ]; then
  if ! [[ "$PDB_AVAILABLE_OBSERVED_EPOCH" =~ ^[0-9]+$ ]] || [ "$PDB_AVAILABLE_OBSERVED_EPOCH" -lt "$PDB_CREATED_EPOCH" ]; then
    PDB_AVAILABLE_OBSERVED_EPOCH="$PDB_CHECK_EPOCH"
    upsert_cli_env "$PDB_AVAILABLE_EPOCH_KEY" "$PDB_AVAILABLE_OBSERVED_EPOCH" >/dev/null
    upsert_cli_env "$PDB_AVAILABLE_AT_KEY" "$(date -u -d "@$PDB_AVAILABLE_OBSERVED_EPOCH" +%Y-%m-%dT%H:%M:%SZ)" >/dev/null
  fi
  PDB_DURATION_EPOCH="$PDB_AVAILABLE_OBSERVED_EPOCH"
  PDB_DURATION_LABEL="COMPLETED_AFTER_OBSERVED"
else
  PDB_DURATION_EPOCH="$PDB_CHECK_EPOCH"
  PDB_DURATION_LABEL="ELAPSED_TIME"
fi

PDB_DURATION_SECONDS=$((PDB_DURATION_EPOCH - PDB_CREATED_EPOCH))
if [ "$PDB_DURATION_SECONDS" -lt 0 ]; then
  PDB_DURATION_SECONDS=0
fi

if [ "$PDB_DURATION_SECONDS" -lt 60 ]; then
  PDB_DURATION_TEXT="${PDB_DURATION_SECONDS}s"
elif [ "$PDB_DURATION_SECONDS" -lt 3600 ]; then
  PDB_DURATION_TEXT="$((PDB_DURATION_SECONDS / 60))m $((PDB_DURATION_SECONDS % 60))s"
else
  PDB_DURATION_TEXT="$((PDB_DURATION_SECONDS / 3600))h $(((PDB_DURATION_SECONDS % 3600) / 60))m"
fi

printf '%-28s | %s\n' \
  "FIELD" "VALUE" \
  "----------------------------" "-----" \
  "NEW_PDB_NAME" "$NEW_PDB_NAME" \
  "NEW_PDB_OCID" "$NEW_PDB_OCID" \
  "PDB_STATE" "$PDB_STATE" \
  "TIME_CREATED" "$PDB_TIME_CREATED" \
  "$PDB_DURATION_LABEL" "$PDB_DURATION_TEXT"

if [ "$PDB_STATE" = "AVAILABLE" ]; then
  printf 'PDB is AVAILABLE. Completion duration is based on the first observed AVAILABLE check.\n'
else
  printf 'Rerun this card while PDB_STATE is PROVISIONING. Continue only when it is AVAILABLE.\n'
fi
  printf '\n%s\n' "wb18_card03"
}

BASH 04 - Enable Database Management for the new PDB

After OCI reports that the PDB is available, register this specific PDB with OCI Database Management. The card reuses the Database Management private endpoint, Vault credential secret, and connection defaults established in Chapter 14; it does not create a second endpoint or expose a password. Enabling Database Management changes the PDB's operational management state and can affect service consumption, so confirm the target PDB before the request is submitted.

BASH 04 - Enable Database Management for the new PDB

Bash
Objective: Enable OCI Database Management for the available PDB by using the existing private endpoint and Vault credential secret. 
wb18_card04() {
  clear
  . ~/workbook/bin/env.sh --quiet || return 1
DBMGMT_ENABLE_RESPONSE_JSON="$JSON_DIR/${NEW_PDB_NAME:-new-pdb}-dbmgmt-enable-response.json"
DBMGMT_ENABLE_ERROR_TXT="$REPORT_DIR/${NEW_PDB_NAME:-new-pdb}-dbmgmt-enable-error.txt"

for name in REGION CDB_NAME NEW_PDB_NAME NEW_PDB_OCID DBMGMT_PASSWORD_SECRET_OCID DBMGMT_PRIVATE_ENDPOINT_OCID DBMGMT_CREDENTIAL_USERNAME DBMGMT_PROTOCOL DBMGMT_PORT DBMGMT_ROLE; do
  value="${!name:-}"
  if [ -z "$value" ]; then
    clear
    printf 'STOP: Missing required variable: %s. Complete Chapter 14 before enabling Database Management.\n' "$name" >&2
    return 1
  fi
done

PDB_STATE="$(
  oci db pluggable-database get \
    --region "$REGION" \
    --pluggable-database-id "$NEW_PDB_OCID" \
    --query 'data."lifecycle-state"' \
    --raw-output
)"

if [ "$PDB_STATE" != "AVAILABLE" ]; then
  clear
  printf 'STOP: %s is %s. Run BASH 03 and wait for AVAILABLE before enabling Database Management.\n' "$NEW_PDB_NAME" "$PDB_STATE" >&2
  return 1
fi

CDB_NAME_LOWER="$(printf '%s' "$CDB_NAME" | tr '[:upper:]' '[:lower:]')"
PDB_NAME_LOWER="$(printf '%s' "$NEW_PDB_NAME" | tr '[:upper:]' '[:lower:]')"
DBMGMT_PDB_SERVICE_NAME="${CDB_NAME_LOWER}_${PDB_NAME_LOWER}.paas.oracle.com"

clear
printf 'Enable OCI Database Management for PDB %s by using service %s? [y/N]: ' \
  "$NEW_PDB_NAME" "$DBMGMT_PDB_SERVICE_NAME"
IFS= read -r DBMGMT_CONFIRM
case "$DBMGMT_CONFIRM" in
  y|Y|yes|YES)
    ;;
  *)
    clear
    printf 'Database Management enablement canceled for %s.\n' "$NEW_PDB_NAME"
    printf '\n%s\n' "wb18_card04"
    return 0
    ;;
esac

oci db pluggable-database enable-pluggable-database-management \
  --region "$REGION" \
  --password-secret-id "$DBMGMT_PASSWORD_SECRET_OCID" \
  --pluggable-database-id "$NEW_PDB_OCID" \
  --private-end-point-id "$DBMGMT_PRIVATE_ENDPOINT_OCID" \
  --service-name "$DBMGMT_PDB_SERVICE_NAME" \
  --user-name "$DBMGMT_CREDENTIAL_USERNAME" \
  --protocol "$DBMGMT_PROTOCOL" \
  --port "$DBMGMT_PORT" \
  --role "$DBMGMT_ROLE" \
  > "$DBMGMT_ENABLE_RESPONSE_JSON" \
  2> "$DBMGMT_ENABLE_ERROR_TXT"
DBMGMT_ENABLE_STATUS=$?

if [ "$DBMGMT_ENABLE_STATUS" -eq 0 ]; then
  DBMGMT_ENABLE_ACTION="ENABLE_REQUEST_SUBMITTED"
elif grep -qi 'already enabled\|request to enable it is already created' "$DBMGMT_ENABLE_ERROR_TXT" "$DBMGMT_ENABLE_RESPONSE_JSON" 2>/dev/null; then
  DBMGMT_ENABLE_ACTION="ALREADY_ENABLED_OR_REQUESTED"
else
  clear
  printf 'STOP: Database Management enablement failed for %s. Review %s.\n' \
    "$NEW_PDB_NAME" "$DBMGMT_ENABLE_ERROR_TXT" >&2
  return 1
fi

upsert_cli_env NEW_PDB_DBMGMT_SERVICE_NAME "$DBMGMT_PDB_SERVICE_NAME" >/dev/null

clear
printf '%-32s | %s\n' \
  "FIELD" "VALUE" \
  "--------------------------------" "-----" \
  "NEW_PDB_NAME" "$NEW_PDB_NAME" \
  "NEW_PDB_OCID" "$NEW_PDB_OCID" \
  "PDB_STATE" "$PDB_STATE" \
  "DBMGMT_PDB_SERVICE_NAME" "$DBMGMT_PDB_SERVICE_NAME" \
  "DBMGMT_ENABLE_ACTION" "$DBMGMT_ENABLE_ACTION" \
  "DBMGMT_ENABLE_RESPONSE_JSON" "$DBMGMT_ENABLE_RESPONSE_JSON" \
  "DBMGMT_ENABLE_ERROR_TXT" "$DBMGMT_ENABLE_ERROR_TXT"
printf '\n%s\n' "wb18_card04"
}

Operational notes

The new PDB is a separate logical database inside CDB01; it can have its own application schemas and service configuration while sharing CDB-level infrastructure. Do not treat AVAILABLE or a submitted Database Management request as an application readiness signal by itself: validate the required PDB services, users, network path, backup policy, application connectivity, and the Database Management managed-database record before onboarding workload.

For the PDB creation API parameters and lifecycle states, see OCI CLI: create a pluggable database, OCI CLI: enable PDB Database Management, and OCI CLI: pluggable database commands.
